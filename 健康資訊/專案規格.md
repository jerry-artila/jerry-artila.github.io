# 《健康資訊》專欄網頁系統 - 軟體需求與系統規格說明書 (SRS)

本文件為 **健康資訊（銀髮親和專欄）** 之軟體需求與系統規格說明書（Software Requirement Specification）。

---

## 📌 一、 專案概述 (Executive Summary)

本專案旨在將權威、專業之健康與預防醫學資訊（如各大醫療媒體報導、名醫養生觀點），轉化為**適合高齡長輩於智慧型手機上順暢閱讀**的數位內容。

針對銀髮族群常見之視力退化、手部操作精細度降低與資訊接收習慣，系統捨棄繁複花俏之視覺干擾，貫徹「樸素清晰、大字好讀、導覽直覺、一目了然」的核心原則，建構行動優先（Mobile-First）之無障礙健康資訊閱讀系統。

系統設有統一首頁（`index.html`），上限彙整展示最近 10 篇精選健康文章摘要卡片（未滿 10 篇時僅陳列已發布篇章與「陸續更新中」提醒），方便長者總覽與點閱。

---

## 📂 二、 系統架構與檔案目錄規劃 (System Architecture & Directory)

### 1. 檔案目錄結構
```
jerry-artila.github.io/健康資訊/
├── 專案規格.md                   # 本系統規格與開發維護規範說明書 (SRS)
├── index.html                  # 專欄首頁：上限彙整最近 10 篇健康文章摘要卡片
├── 台北地區-失智檢測.md            # 文章原始 Markdown 摘要與各大醫院門診指引
├── 台北地區-失智檢測.html          # 銀髮友善行動端發布網頁 (同名輸出)
├── 基隆長庚-失智檢測.md            # 文章原始 Markdown 摘要與醫療指引
├── 基隆長庚-失智檢測.html          # 銀髮友善行動端發布網頁 (同名輸出)
├── 預防失智-認真咀嚼.md            # 文章原始 Markdown 摘要與結構化內容
├── 預防失智-認真咀嚼.html          # 銀髮友善行動端發布網頁 (同名輸出)
└── （未來擴充文章：主題-子題.html / .md）
```

### 2. 命名與產出原則
- **同名產出**：每篇收錄之健康主題，先以標準 Markdown 撰寫結構化內容（如 `[主題]-[特色標題].md`），再輸出成對應之同名發布檔（`[主題]-[特色標題].html`）。
- **首頁彙整更新**：每當產出新篇章時，需同步更新 `index.html` 之「最近 10 篇摘要卡片列表」與漢堡選單目錄。
- **零依賴單檔架構（Zero-Dependency Standalone）**：HTML 檔案內部封裝所需之 CSS 與 JavaScript，不依賴外部大型框架或第三方 CDN，確保在長輩手機弱網環境或離線環境下均能秒開、不跑版。

## 🎨 三、 UI/UX 與銀髮親和視覺規範 (Senior-Friendly UI/UX Standards)

### 1. 樸素極簡視覺風格 (Uncluttered & Plain Design)
- **拒絕視覺噪音**：不使用跑馬燈、突兀彈窗、繁複漸層與過度動畫，保留大量閱讀留白。
- **護眼溫和色系**：
  - **背景色**：採用柔和護眼米紙白（`#faf8f5`），消除純白螢幕帶給長輩眼睛的刺眼眩光感。
  - **文本色**：高對比深碳灰（`#222222`），字級清晰立體，符合 WCAG AAA 等級高對比度規範。
  - **主調色**：穩重內斂之草木綠（`#2b5c46`）與暖灰分隔線（`#e2ded7`），營造沉靜健康的閱讀氛圍。

### 2. 三級動態字級控制系統 (3-Level Dynamic Typography)
全站頂部工具列固定提供明確、易按的切換按鈕，支援三段式字級即時切換：

| 字級級別 | 內文字級 | 標題字級 (h1/h2) | 行高 (Line Height) | 適用情境 |
| :--- | :--- | :--- | :--- | :--- |
| **標準（預設）** | `20px` | `28px / 23px` | `1.8` | 一般長者或常規閱讀 |
| **大** | `24px` | `33px / 27px` | `1.85` | 視力輕微模糊、需舒適大字者 |
| **特大** | `28px` | `38px / 32px` | `1.9` | 嚴重老花或戶外強光下閱讀 |

- **狀態持久化**：使用瀏覽器 `localStorage`（Key: `health_font_level`）記錄讀者選擇，在首頁與各文章內頁切換時，自動保持相同字級，不需重複設定。

### 3. 行動觸控友善性 (Mobile Touch Accessibility)
- **大尺寸點擊目標**：所有按鈕（漢堡選單、字體切換、閱讀全文按鈕、關閉按鈕、回到頂部）點擊範圍均 $\ge 44 \sim 48\text{ px}$，有效防範長輩手震誤觸。
- **單手操作輔助**：頁面右下角配置浮動「▲ 回到頂部」按鈕，長文滾動超過 300px 自動浮現，方便一鍵平滑返回頂部。

## 📑 四、 專欄首頁模組規格 (`index.html`)

### 1. 頁面功能定位
`index.html` 作為整個《健康資訊》單元的樞紐入口，以乾淨、明晰的**摘要卡片流**呈現最新發布之健康新知。

### 2. 文章摘要卡片架構 (Article Cards Architecture)
首頁主區塊陳列最新收錄文章之摘要卡片（上限為最近 10 篇）。在文章逐步累積期間，嚴格遵循**「只陳列真實已發布文章，不預告或虛構後續專題」**原則，目前以 1 篇發布文章搭配樸素清晰的「陸續更新中」提示卡片呈現：

1. **已發布文章卡片組成**：
   - **主題分類徽章 (Category Badge)**：清楚標示分類領域（如 `🧠 大腦保健`）。
   - **發布日期與出處 (Meta)**：標註權威出處媒體與更新時間（如 `2026/07/17 · TVBS 健康2.0`）。
   - **文章標題 (Card Title)**：粗體醒目字級，超連結直通對應的文章 `.html` 檔案。
   - **精要摘要 (Card Summary)**：提取文章中最核心的 2～3 句結論（約 80～120 字），長者一目了然。
   - **大面積操作按鈕 (Call to Action)**：配置高對比森林綠之「`閱讀全文 ➔`」大按鈕（高度 $\ge 48\text{px}$）。
2. **「陸續更新中」提醒區塊**：
   - 於卡片列表底部以虛線溫和邊框呈現「🌱 更多健康資訊 陸續更新中」提示，不列出未確認之具體篇名或主題，保持風格樸素客觀。

## 🧭 五、 漢堡選單架構 (Drawer Navigation)

為便於長者在首頁與各文章之間穿梭，系統建置簡潔之抽屜式側邊選單（Off-Canvas Drawer）：

1. **觸發與呈現**：
   - 頂部導覽列左側常駐 `☰ 選單` 大按鈕，點擊後自左側平滑滑出選單。
   - 配置半透明黑色遮罩，點擊遮罩外側或按鍵盤 `Esc` 均能迅速關閉。
2. **選單分類結構**：
   - 常駐「🏠 專欄首頁（最新文章）」連結。
   - 「健康專題文章」列表：僅列出目前真實已發布之文章項目。
   - 當前正在瀏覽之頁面以特殊高亮底色與綠色邊線標示（`current` 狀態）。
   - 選單底部常駐簡潔溫和的「🌱 陸續更新中」提示文字，避免多餘文字干擾。

## 📝 六、 內容結構與版面編排規範 (Content Structure Standards)

每篇產出的健康文章須遵循以下結構化排版層級：

1. **主文章標題 (`h1`)**：清楚點出問題與關鍵解答，字體加粗、醒目。
2. **元資訊卡 (Meta Box)**：
   - 清楚註記出處媒體（附安全超連結）、受訪專科醫師/專家、發布與更新日期。
3. **核心結論提要框 (Key Takeaway Box)**：
   - 以淺綠色高對比重點框呈現，長輩即便不細讀全文，亦能在 10 秒內掌握最核心的保健建議。
4. **正文綱目分類 (`h2`, `ol`, `ul`)**：
   - 善用清晰的 Emoji 圖示（如 📌、🧠、⚡、🥗、💡）作為章節視覺導航。
   - 醫療術語以粗體強化，段落長度控制在 3～4 行以內，避免密集大段文字造成視覺壓迫。
5. **警訊與注意事項標籤 (Caution Note)**：
   - 針對常見錯誤迷思或注意事項（如「切忌吃軟不吃硬」），以淡黃色警告框予以醒目標記。

## 🚀 七、 維護與演進路線 (Maintenance & Roadmap)

1. **新文章發布標準作業流程（SOP）**：
   - 步驟一：擷取來源資料並整理為 `[主題]-[子題].md`。
   - 步驟二：輸出高齡友善的同名 `[主題]-[子題].html`。
   - 步驟三：更新 `index.html` 頂端之卡片列表（推入最新文章並維持總數 10 篇），同步更新漢堡選單。
2. **語音朗讀支援（TTS）**：
   - 未來可評估整合 Web Speech API，提供「一鍵朗讀文章」之無障礙語音播放功能，進一步友善重度弱視長輩。
